# 0.4.0 实时成长面板

0.4.0小队击杀会同时更新全队符合条件的已装备戒指，每枚获得完整进度。面板仍显示每个实例自己的成长，并向客户端广播只读快照；背包中未装备戒指可以查看，但不参与击杀奖励。升级特效按每个实际升级的佩戴者合并，同一人多枚升级只一次。

已实现独立的可移动、可关闭成长面板，通过戒指的“查看生长之戒 / Inspect Evergrowth Ring”动作打开，或在服务器控制台输入 `!er_panel [角色UUID]`。面板可保持打开，击杀、升级和换装后接收服务器推送，不需要反复关闭再打开。

显示每枚戒指实例的等级、当前进度、本级升级所需总进度、距离升级还差多少、进度条、击杀数，以及六项属性、AC、法术DC、六项豁免、攻击、通用伤害、技能检定、法术位上限、先攻、移动、暴击门槛、动作/附赠动作、13种攻击附伤。已佩戴戒指还显示同一角色两枚戒指的合计计算值。显示的是戒指直接加成，不是角色面板的完整最终值；属性调整值、其他装备、抗性和技能伤害包等另由游戏结算。

下拉菜单可以选择已经登记且当前已加载的戒指。佩戴过的戒指和0.3.0通过TemplateAddedTo生成的戒指会被登记；登记索引随存档保存。卸下后仍可查看潜在加成，明确标记未佩戴。旧版从未佩戴过的戒指需先佩戴一次登记；未加载区域内的实体不伪造实时数据，暂不列出。

## 更新路线

服务器保留唯一经验写入权。NetChannel `RingPanel_v1` 只允许客户端请求只读快照；客户端提交Level/HP等字段会被忽略，不提供修改经验或加成的接口。成长UserVar依然是服务器专用，通过快照同步显示数据，而不是把经验开放给客户端写入。

每次有效击杀（即使没有升级）、装备核对后主动推送。面板打开时，客户端每30 Tick请求一次快照作为兜底；面板关闭时停止主动轮询。实际延迟受帧率、暂停和网络影响，不能把“实时”理解成每次引擎计算同一帧内立即显示。收到延迟的旧Revision不会覆盖新的显示。载入存档时隐藏旧面板，重新取得当前数据后可再次打开。

界面采用BG3SE自己的 `Ext.IMGUI`，没有猜测或改写游戏原生tooltip的Noesis节点。核对了源码 `ClientIMGUI.inl`、`ExtIdeHelpers.lua` 中NewWindow、AddText、AddCombo、AddProgressBar、Label、Value、Overlay、Open、SelectedIndex、OnChange和OnClick；进度条和下拉菜单使用原生属性。中文/英文同时标注，SE默认字体根据游戏语言加载；中文游戏的默认中文字体路径在SE源码中存在。不同字体、缩放、图形后端和手柄操作尚未实际验证。

**原版背包的鼠标悬浮卡片仍然是静态说明**，会提示打开成长面板。这次没有实现把原生物品卡变成动态进度卡；动态数据在独立面板中。这样避免修改共享Stats/本地化handle使多枚戒指互相串用文本。

## 验证边界

已通过Lua 5.4客户端适配器测试：同一窗口不重建即可更新等级和进度、切换实例并保留选择、显示所有加成、打开时轮询、关闭后不自动重开、忽略旧快照。服务器测试覆盖未升级也推送、读请求不能改经验、双戒指合计、登记后卸下仍能查看。

**没有实际运行Windows BG3、SE客户端、图形后端或网络联机。** 这些测试不是渲染测试。若面板未出现或出现Lua错误，保留日志并使用 `!er_status` 读取核心成长数据；经验系统不依赖面板成功创建。
