# 戒指实时等级/进度显示：仅评估，未实现

历史记录：本文件描述0.2.0当时的评估。0.3.0已实现独立实时面板，当前行为请看[UI_PANEL.md](UI_PANEL.md)。

用户本次要求只讨论此项，暂不修改界面。因此0.2.0没有新增实时物品提示、进度条或自定义详情面板；仍使用已有的查看动作与控制台读取。

需要显示的数据已存在于每枚戒指实例的UserVar中：Level；当前进度ProgressHP/100；本级升级需求10+5*Level；距离下一级还差(1000+500*Level-ProgressHP)/100。也可据此计算进度百分比。即使一次击杀连续升级，也能显示结算后的新等级与剩余进度。

BG3SE官方API支持客户端Noesis UI、自定义ViewModel、变更通知和UserVars同步，因此可以设计打开后随击杀自动更新的戒指详情面板。来源：[BG3SE API，Noesis UI与User variables](https://github.com/Norbyte/bg3se/blob/4c85de82264b985d2796cddd012b08847c6527fd/Docs/API.md)。这是基于已存在接口的可行性判断，不是已完成的游戏内功能验证。

合理的数据路线是：服务器更新戒指实例状态 → 向客户端同步只读成长数据 → 客户端按当前选中的戒指实例绑定文本/进度条。当前版本的成长变量是服务器专用，后续实施需一并调整两端注册与同步，不应让客户端写入经验。

原版背包悬浮说明是另一条适配路线。必须先在实际游戏中确认当前悬浮物品的实例标识、可修改的tooltip ViewModel、物品提示缓存，以及键鼠/手柄检查界面的差异。目前没有验证这些具体绑定点，因此不能承诺“原版说明保持悬停不关闭也会立即刷新”。不能仅改共享Stats或共享本地化handle，否则多枚不同等级的戒指可能串用同一段文本。

若直接操作Noesis对象，按v33及以上官方要求通过Ext.UI.Defer在UI线程执行；游戏状态写入留在服务器/游戏线程。具体窗口和绑定对象名称需实际检查，不能猜造。
